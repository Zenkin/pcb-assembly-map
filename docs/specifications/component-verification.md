# Техническое задание: модуль проверки компонентов

Функциональные требования к фиксации фактических номиналов, контролю допуска, отчётности и сохранности данных при обновлении BOM в приложении SolderMap.

| **Статус**             | Утверждено                                        |
|------------------------|---------------------------------------------------|
| **Версия**             | 1.0                                               |
| **Дата утверждения**   | 25 июля 2026 г.                                   |
| **Объект**             | Настольное приложение SolderMap                   |
| **Область**            | Проверка каждого позиционного обозначения отдельно |
| **Основной документ**  | Этот Markdown-файл                                |
| **Порядок изменений**  | Через отдельный pull request с обновлением версии |

**Ключевой принцип**

> **«Проверен / не проверен» — самостоятельный бинарный статус. Результат контроля номинала вычисляется отдельно и не блокирует проверку.**

# 1. Общие сведения

## 1.1. Назначение документа

Настоящее техническое задание определяет требования к модулю проверки компонентов в приложении «Карта сборки платы». Модуль предназначен для фиксации результатов ручной проверки каждого компонента, сравнения измеренного номинала с данными BOM, отображения состояния проверки и формирования отчётности.

## 1.2. Цели разработки

- Снизить вероятность ошибок при установке, пайке и маркировке компонентов.

- Обеспечить проверку каждого позиционного обозначения отдельно, даже если несколько компонентов объединены одной строкой BOM.

- Сохранить измерения, комментарии и подтверждение проверки в составе проекта.

- Не смешивать состояние проверки с уже существующими состояниями «Установлен / Припаян».

- Обеспечить контролируемое обновление BOM без незаметной потери результатов.

## 1.3. Границы первой версии

Статус проверки и комментарий доступны для всех компонентов. Числовой ввод, автоматическое приведение единиц, расчёт отклонения и контроль допуска в первой версии реализуются для резисторов и конденсаторов.

# 2. Термины и логика состояний

| **Термин**          | **Определение**                                                                                               |
|---------------------|---------------------------------------------------------------------------------------------------------------|
| Компонент           | Отдельное позиционное обозначение на плате: R1, R2, C4 и т. п.                                                |
| BOM-номинал         | Номинал из импортированной BOM либо ручной опорный номинал, заданный только для конкретного компонента.       |
| Фактический номинал | Измеренное значение, введённое пользователем как число и выбранная единица.                                   |
| Допуск              | Необязательное процентное поле BOM в формате ±N %.                                                            |
| Статус проверки     | Бинарное состояние «Проверен / не проверен».                                                                  |
| Результат контроля  | Вычисляемое состояние: «в допуске», «вне допуска», «без допуска», «сравнение невозможно» или «нет измерения». |
| Резервная копия     | Снимок данных проверок, создаваемый перед изменением BOM или восстановлением.                                 |

| **Разделение состояний.** Галочка «Проверен» не зависит от результата контроля и от статуса «Установлен / Припаян». Компонент разрешено отметить проверенным без фактического номинала, например после визуального контроля установки или маркировки. |
|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|

# 3. Исходные данные и расширение BOM

**BOM-01** Система должна продолжать поддерживать существующий импорт BOM.

**BOM-02** Для каждой позиции BOM должно поддерживаться необязательное поле допуска в процентах.

**BOM-03** Поддерживаемый формат допуска первой версии: симметричный процентный допуск ±N %. Значение N должно быть неотрицательным числом.

**BOM-04** Отсутствие допуска не должно считаться ошибкой импорта и не должно препятствовать проверке компонента.

**BOM-05** После раскрытия группового списка обозначений проверка и данные должны храниться для каждого обозначения отдельно.

**BOM-06** Если BOM-номинал отсутствует или не распознан, пользователь может задать ручной опорный номинал в окне проверки.

**BOM-07** Ручной опорный номинал применяется только к текущему компоненту и не изменяет остальные компоненты той же строки или группы BOM.

# 4. Модель данных проверки

| **Поле**                | **Обязательность**   | **Формат**      | **Правило**                       |
|-------------------------|----------------------|-----------------|-----------------------------------|
| Позиционное обозначение | Да                   | Строка          | Ключ привязки: R1, C4 и т. п.     |
| Проверен                | Да                   | Логический      | По умолчанию «нет»                |
| Фактическое значение    | Нет                  | Число           | Принимаются запятая и точка       |
| Единица                 | При наличии значения | Перечисление    | Зависит от типа компонента        |
| Комментарий             | Нет                  | Текст           | Сохраняется независимо от статуса |
| Ручной BOM-номинал      | Нет                  | Число + единица | Локальный override компонента     |
| Отклонение              | Вычисляемое          | Абсолютное и %  | Не вводится пользователем         |
| Результат контроля      | Вычисляемое          | Перечисление    | Не заменяет статус проверки       |

## 4.1. Единицы первой версии

- Резисторы: Ом, кОм, МОм.

- Конденсаторы: пФ, нФ, мкФ, мФ.

- При сравнении значения автоматически приводятся к общей базовой единице.

- Числа с десятичной запятой и точкой должны интерпретироваться одинаково: 98,5 = 98.5.

# 5. Компактное окно проверки

## 5.1. Способы открытия

**UI-01** Окно проверки должно открываться двойным щелчком по компоненту на плате.

**UI-02** Окно проверки должно открываться кнопкой «Проверка» в карточке компонента или в списке компонентов.

**UI-03** Окно проверки должно открываться пунктом контекстного меню компонента.

**UI-04** Одновременно допускается только одно окно проверки. При открытии другого компонента текущее окно закрывается, после чего открывается новое.

## 5.2. Состав окна

- Позиционное обозначение компонента.

- BOM-номинал; если он отсутствует или не распознан — предупреждение и поля ручного опорного номинала.

- Числовое поле фактического номинала.

- Отдельный список единиц, соответствующий типу компонента.

- Необязательный комментарий.

- Галочка «Проверен».

- Абсолютное и процентное отклонение при возможности сравнения.

- Допустимый диапазон при наличии допуска.

- Результат контроля и предупреждения.

- Кратковременная индикация «Сохранено» после успешного автосохранения.

## 5.3. Автосохранение и валидация

**UI-05** Фактический номинал, единица, комментарий, ручной BOM-номинал и галочка должны сохраняться автоматически после корректного изменения.

**UI-06** Поля и галочка независимы: данные разрешено сохранять до и после изменения статуса «Проверен».

**UI-07** Некорректное или незавершённое числовое значение не должно записываться в проект; поле должно визуально подсвечиваться как ошибочное.

**UI-08** После исправления значения система должна выполнить сохранение и обновить расчёт.

**UI-09** При закрытии окна некорректный несохранённый ввод отбрасывается; последнее корректно сохранённое значение остаётся без изменений.

# 6. Расчёт отклонения и контроль допуска

Вычисления выполняются после нормализации единиц. Обозначим:

- N — опорный BOM-номинал в базовой единице;

- M — фактический номинал в той же базовой единице;

- T — процент допуска, если он задан.

| **Формулы.** Абсолютное отклонение: Δ = M − N. Процентное отклонение: δ = (M − N) / N × 100 %. Допустимый диапазон: \[N × (1 − T/100); N × (1 + T/100)\]. |
|-----------------------------------------------------------------------------------------------------------------------------------------------------------|

**CALC-01** Система должна показывать абсолютное отклонение со знаком и в удобной единице измерения.

**CALC-02** Система должна показывать процентное отклонение со знаком.

**CALC-03** При наличии допуска система должна показывать нижнюю и верхнюю границы допустимого диапазона.

**CALC-04** Если фактическое значение находится внутри диапазона, включая обе границы, результат контроля — «В допуске».

**CALC-05** Если фактическое значение ниже нижней или выше верхней границы, результат — «Вне допуска» и выводится предупреждение.

**CALC-06** Предупреждение о выходе за допуск не должно блокировать установку галочки «Проверен».

**CALC-07** Если допуск не задан, система показывает абсолютное и процентное отклонение, но не выносит заключение о соответствии допуску.

**CALC-08** Если опорный номинал отсутствует или не распознан, сравнение не выполняется; пользователь получает предупреждение и предложение задать номинал вручную.

**CALC-09** Если фактический номинал не введён, компонент всё равно может иметь статус «Проверен», а результат числового контроля отображается как «Нет измерения».

**CALC-10** Деление на ноль и другие математически неопределённые случаи должны обрабатываться без аварийного завершения и отображаться как невозможность сравнения.

# 7. Индикация в основном интерфейсе

**IND-01** Проверенный компонент на плате должен отмечаться отдельным значком проверки.

**IND-02** Значок проверки не должен изменять цвет компонента и не должен перекрывать существующую цветовую индикацию «Установлен / Припаян».

**IND-03** Текстовый статус «Проверен / не проверен» должен отображаться в списке компонентов.

**IND-04** Основная карточка компонента должна показывать статус, фактический номинал, результат контроля и комментарий.

**IND-05** В списке компонентов должны отображаться как минимум статус и фактический номинал.

# 8. Фильтры и сводка по плате

## 8.1. Фильтры

**FLT-01** Должны быть доступны фильтры «Проверен», «Не проверен» и «Вне допуска».

**FLT-02** Фильтр «Вне допуска» включает только компоненты, у которых задан допуск, введён фактический номинал и установлен факт превышения допуска.

**FLT-03** Компоненты без допуска и компоненты, которые невозможно сравнить, не должны попадать в фильтр «Вне допуска».

## 8.2. Сводка

Общая сводка по плате должна отображать:

- общее количество компонентов;

- количество компонентов со статусом «Проверен»;

- количество проверенных компонентов «В допуске»;

- количество проверенных компонентов «Вне допуска»;

- количество проверенных компонентов без заданного допуска;

- количество компонентов с комментариями.

| **Правило подсчёта.** Показатели «в допуске», «вне допуска» и «без допуска» рассчитываются только для компонентов со статусом «Проверен». Компоненты без фактического номинала не относятся к категориям «в допуске» или «вне допуска». |
|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|

# 9. Экспорт результатов

**EXP-01** Система должна экспортировать результаты в PDF, CSV и Excel (.xlsx).

**EXP-02** В отчёт должны включаться все компоненты, включая непроверенные, независимо от текущего фильтра интерфейса.

**EXP-03** Для каждого компонента отчёт должен содержать поля из таблицы 1.

| **№** | **Поле отчёта**         | **Примечание**                                                               |
|-------|-------------------------|------------------------------------------------------------------------------|
| 1     | Позиционное обозначение | R1, C4 и т. п.                                                               |
| 2     | Тип компонента          | Резистор, конденсатор и др.                                                  |
| 3     | Номинал BOM             | Исходный либо ручной опорный                                                 |
| 4     | Допуск                  | Пусто, если не задан                                                         |
| 5     | Фактический номинал     | Число и единица                                                              |
| 6     | Абсолютное отклонение   | При возможности сравнения                                                    |
| 7     | Процентное отклонение   | При возможности сравнения                                                    |
| 8     | Допустимый диапазон     | При наличии допуска                                                          |
| 9     | Статус проверки         | Проверен / не проверен                                                       |
| 10    | Результат контроля      | В допуске / вне допуска / без допуска / сравнение невозможно / нет измерения |
| 11    | Комментарий             | Полный текст комментария                                                     |

**EXP-04** PDF должен быть пригоден для печати: иметь заголовок проекта/платы, дату формирования, повторяемую шапку таблицы и нумерацию страниц.

**EXP-05** CSV должен сохранять значения без потери кириллицы и содержать однозначные заголовки столбцов.

**EXP-06** Excel-файл должен содержать одну строку на одно позиционное обозначение и быть пригоден для фильтрации по столбцам.

# 10. Повторный импорт и обновление BOM

## 10.1. Сопоставление

**UPD-01** При обновлении BOM система должна сопоставлять компоненты прежде всего по позиционному обозначению.

**UPD-02** Если тип и номинал компонента не изменились, существующие данные проверки должны сохраняться.

**UPD-03** Если изменился тип или номинал компонента, все данные его проверки подлежат полному сбросу: статус, фактический номинал, единица, комментарий, ручной опорный номинал и вычисляемые результаты.

## 10.2. Конфликты

Обновление считается конфликтным и требует решения пользователя, если:

- не удалось однозначно сопоставить старый и новый компонент;

- позиционное обозначение исчезло из новой BOM;

- одно позиционное обозначение найдено в нескольких строках;

- одновременно изменились тип и номинал компонента.

**UPD-04** До применения изменений система должна показать список затронутых компонентов и характер изменения по каждому из них.

**UPD-05** Перед удалением данных система должна запросить подтверждение пользователя.

**UPD-06** В диалоге подтверждения должна быть доступна возможность экспортировать старые результаты.

**UPD-07** До применения любой изменённой BOM должна автоматически создаваться резервная копия текущих проверок.

**UPD-08** Без подтверждения конфликтное обновление не должно необратимо изменять данные проверок.

# 11. Резервные копии и восстановление

**BKP-01** Внутри проекта должны храниться последние 10 резервных копий.

**BKP-02** При создании 11-й копии самая старая копия удаляется автоматически.

**BKP-03** Для каждой копии должны отображаться дата и время, а также причина создания.

**BKP-04** Должно поддерживаться восстановление всей копии целиком.

**BKP-05** Должно поддерживаться восстановление выбранных компонентов; данные остальных компонентов при этом не изменяются.

**BKP-06** Перед восстановлением должна автоматически создаваться копия текущего состояния.

**BKP-07** Перед восстановлением система должна показать сравнение сохранённых и текущих данных.

**BKP-08** Перезапись конфликтующих компонентов должна выполняться только после отдельного подтверждения пользователя.

**BKP-09** После успешного восстановления интерфейс, фильтры, сводка и экспорт должны использовать восстановленные данные без повторного открытия проекта.

# 12. Нефункциональные требования

**NFR-01** Все операции ввода и проверки должны выполняться без блокирования основного интерфейса.

**NFR-02** Автосохранение должно быть устойчиво к быстрому последовательному редактированию полей и переключению компонентов.

**NFR-03** После штатного закрытия и повторного открытия проекта все сохранённые данные проверок и резервные копии должны восстанавливаться.

**NFR-04** Ошибка сохранения должна быть явно показана пользователю; интерфейс не должен отображать ложный статус «Сохранено».

**NFR-05** Новые значки и элементы управления должны быть различимы при стандартном масштабе интерфейса и не закрывать обозначение компонента.

**NFR-06** Расчёты должны выполняться с точностью, достаточной для корректного сравнения с границами допуска; округление применяется только при отображении.

**NFR-07** Форматы PDF, CSV и XLSX должны формироваться без зависимости от наличия Microsoft Office на компьютере пользователя.

**NFR-08** Изменение BOM, восстановление и экспорт не должны повреждать исходные файлы BOM.

# 13. Критерии приёмки

Функция считается принятой после успешного выполнения следующих сценариев:

| **ID** | **Сценарий**             | **Ожидаемый результат**                                                                      |
|--------|--------------------------|----------------------------------------------------------------------------------------------|
| AT-01  | Индивидуальная проверка  | Для R1, R2 и R3 из одной строки BOM сохраняются разные статусы, измерения и комментарии.     |
| AT-02  | Три способа открытия     | Окно одной и той же проверки открывается с платы, из карточки/списка и из контекстного меню. |
| AT-03  | Автосохранение           | Корректное изменение сохраняется без кнопки; появляется краткий статус «Сохранено».          |
| AT-04  | Ошибка ввода             | Некорректное число подсвечивается и не заменяет последнее корректное значение.               |
| AT-05  | Приведение резисторов    | 0,1 кОм и 100 Ом сравниваются как равные; отклонение равно 0.                                |
| AT-06  | Приведение конденсаторов | 0.1 мкФ и 100 нФ сравниваются как равные.                                                    |
| AT-07  | Контроль допуска         | Для 100 Ом ±5 % диапазон равен 95–105 Ом; 106 Ом помечается «Вне допуска».                   |
| AT-08  | Граница допуска          | 95 и 105 Ом считаются значениями в допуске.                                                  |
| AT-09  | Проверка без измерения   | Компонент отмечается «Проверен» при пустом фактическом номинале.                             |
| AT-10  | Нет допуска              | Отклонение показывается, но заключение «в допуске / вне допуска» не формируется.             |

# 14. Ограничения и вопросы вне объёма

- В первой версии не требуется автоматический числовой контроль катушек индуктивности, диодов, микросхем и прочих типов компонентов.

- Процентный допуск поддерживается в симметричном формате ±N %. Абсолютный и асимметричный допуск не входят в первую версию.

- Статус «Проверен» не является автоматическим заключением о пригодности компонента.

- Конкретная технология хранения, библиотека экспорта и внутренняя архитектура определяются после анализа текущего проекта при соблюдении настоящего ТЗ.

- Изменения существующего поведения «Установлен / Припаян», кроме совместимости с новым значком, в объём работ не входят.

# 15. Итоговая матрица правил

| Ошибочный числовой ввод                                     | Подсветка ошибки; значение не сохраняется          | Да, статус независим          |
